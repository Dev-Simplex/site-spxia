## 1. Top 5 aprendizados

1. Os melhores heros mostram **o produto funcionando**, com chat, caixa de entrada ou notificação. Nenhum deles depende de número solto.
2. Uma **forma grande da marca, cortada pela borda, atrás do card de produto** (Pipefy, Jetimob, Kenlo) é exatamente o nosso símbolo verde. Repetir em toda seção visual.
3. A ilustração em traço funciona **espiando por trás da interface** (Notion) ou **sozinha ao lado do título** (Intercom). Uma por seção, nunca uma cena cheia.
4. **Pessoa real com 2 ou 3 cards de notificação** (Imobzi, Zendesk, Gusto) passa confiança e calor numa tela só, sem parágrafo.
5. Os títulos têm de 4 a 8 palavras e nenhum kicker. O resto do texto vira **rótulo dentro da interface**, como "CRM Atualizado" e "Lead QUENTE" (RD Station, Kenlo).

## 3. Padrões de animação no scroll

### Regras comuns

- Anime só `transform`, `opacity` e `clip-path`. Nada de `height`, `top` ou `box-shadow` a cada frame.
- `MotionConfig reducedMotion="user"` (já usado em `problema.tsx`) desliga transform e layout. Ele **não** para valores ligados ao scroll (`useScroll`/`useTransform` no `style`), `pathLength`, `clipPath` nem cor. Nesses casos, cheque `useReducedMotion()` e passe um valor fixo.
- `animation-timeline` em CSS funciona no Chrome/Edge 115+ e no Safari 26+. No Firefox, o caniuse só lista a partir da versão 161, e o MDN marca o recurso como "Limited availability". Use sempre dentro de `@supports` e `@media (prefers-reduced-motion: no-preference)`. O fallback é o estado final, estático.
- Keyframes em CSS vão num CSS module da seção (`app/globals.css` é do coordenador).
- No celular, sticky alto e parallax só a partir de `md`.

### P1. Revelação ao entrar na tela

- Exemplos ao vivo: https://motion.dev/examples/react-scroll-triggered · CSS: https://scroll-driven-animations.style/demos/image-reveal/css/
- Onde: títulos, ilustrações, os balões da caixa de entrada e os cards flutuantes do hero, em sequência.
- Como: **o `reveal()` já existe em `components/sections/problema.tsx`**. Reutilize; não crie outro.
- Custo: baixo. Usa IntersectionObserver e roda uma vez.
- Reduced motion: com `MotionConfig reducedMotion="user"`, vira só fade.

```tsx
import { MotionConfig, motion } from "motion/react"
import { reveal } from "@/components/sections/problema"

<MotionConfig reducedMotion="user">
  <motion.h2 {...reveal()}>Sua rotina pode ser <b>mais simples.</b></motion.h2>
  <ul>
    {mensagens.map((msg, i) => (
      <motion.li key={msg.id} {...reveal(0.2 + i * 0.15)}>{msg.texto}</motion.li>
    ))}
  </ul>
</MotionConfig>
```

### P2. Parallax leve das formas e ilustrações

- Exemplos ao vivo: https://motion.dev/examples/react-parallax · CSS: https://scroll-driven-animations.style/demos/parallax-carousel/css/
- Onde: o símbolo verde atrás da pessoa no hero e a forma dentro de cada `ShapePanel`. A forma anda ±32 px e a ilustração ±12 px. O texto nunca se move.
- Como: `useScroll` com `target` no painel + `useTransform`.
- Custo: baixo a médio, com 2 camadas de transform por painel. Limite a 4 painéis no site.
- Reduced motion: `useReducedMotion()` zera o deslocamento.

```tsx
function ShapeParallax({ children }: { children: React.ReactNode }) {
  const ref = useRef<HTMLDivElement>(null)
  const reduce = useReducedMotion()
  const { scrollYProgress } = useScroll({ target: ref, offset: ["start end", "end start"] })
  const yForma = useTransform(scrollYProgress, [0, 1], reduce ? [0, 0] : [32, -32])
  const yArte = useTransform(scrollYProgress, [0, 1], reduce ? [0, 0] : [12, -12])
  return (
    <div ref={ref} className="relative isolate overflow-hidden rounded-[2rem] bg-surface">
      <motion.img src="/images/formas/simbolo-verde.svg" alt="" aria-hidden
        style={{ y: yForma }} className="absolute -right-1/4 -top-1/4 -z-10 w-[120%]" />
      <motion.div style={{ y: yArte }}>{children}</motion.div>
    </div>
  )
}
```

### P3. Seção sticky que troca o conteúdo

- Exemplos ao vivo: HubSpot https://www.hubspot.com/ (a coluna "Growing a business is hard…" fica presa enquanto os cards rolam; `position: sticky` confirmado) e Zenvia https://zenvia.com/ (`sticky-section` "Zenvia Customer Cloud").
- Onde: **Como funciona.** A ilustração do passo (`passo-1-diagnostico` … `passo-4-evolucao`) fica presa à esquerda e troca a cada passo. Os 4 passos ficam à direita, com o ativo em Azul Pulso.
- Alternativa: Chat SPX → VoxIA em Soluções. Ela troca o bento aprovado no mockup, então só entra se o usuário pedir.
- **Não reaproveite `components/ui/sticky-scroll-reveal.tsx`**. Ele rola dentro de uma caixa de 30rem (o scroll fica preso nela) e usa os pretos da marca antiga.
- Custo: médio. Há um `setState` só na troca (4 estados) e nenhum trabalho a cada frame.
- Reduced motion: a troca vira só fade. Abaixo de `md`, sem sticky: cada passo mostra a própria ilustração.

```tsx
const ref = useRef<HTMLElement>(null)
const { scrollYProgress } = useScroll({ target: ref, offset: ["start start", "end end"] })
const [ativo, setAtivo] = useState(0)
useMotionValueEvent(scrollYProgress, "change", (v) => setAtivo(Math.min(3, Math.floor(v * 4))))

<section ref={ref} className="relative md:h-[300vh]">
  <div className="grid gap-10 md:sticky md:top-0 md:h-screen md:grid-cols-2 md:items-center">
    <AnimatePresence mode="wait">
      <motion.div key={ativo} initial={{ opacity: 0, y: 24 }} animate={{ opacity: 1, y: 0 }} exit={{ opacity: 0 }}>
        <Image src={passos[ativo].ilustracao} alt="" width={560} height={560} />
      </motion.div>
    </AnimatePresence>
    <ListaPassos ativo={ativo} progresso={scrollYProgress} /> {/* os 4 textos ficam sempre no DOM */}
  </div>
</section>
```

### P4. Barra de progresso

- Exemplos ao vivo: https://scroll-driven-animations.style/demos/progress-bar/css/ · https://motion.dev/examples/react-scroll-linked
- Onde: a página toda. **Já existe**: `components/ui/scroll-progress.tsx`, com 3 px em Azul Pulso e spring, montada em `app/page.tsx`. Mantenha e não duplique.
- Custo: muito baixo, só `scaleX`.
- Reduced motion: o componente atual já tira o spring. A barra continua, porque é resposta direta ao scroll.

```css
/* Versão só CSS, caso um dia queira tirar o JS da barra */
.progresso { position: fixed; inset: 0 0 auto; height: 3px; background: var(--primary);
  transform-origin: 0 50%; scale: 0 1; }
@supports (animation-timeline: scroll()) {
  .progresso { animation: progresso linear both; animation-timeline: scroll(root); }
}
@keyframes progresso { to { scale: 1 1; } }
```

### P5. Desenho do traço (stroke)

- Exemplo ao vivo: https://motion.dev/examples/react-path-drawing
- **Achado:** todos os SVGs da SPXia só têm preenchimento, sem nenhum `stroke`. Isso vale para as formas e para `arte-camiseta.svg` (52 paths) e `mascotes-dupla.svg` (49 paths). As ilustrações novas chegam em PNG, então não têm path nenhum. `pathLength` não desenha nada disso.
- Onde: traço de verdade só em linhas novas, como o ✓ dos cards do VoxIA ou o conector dos passos. Para ilustrações, use uma máscara que "pinta" da esquerda para a direita.
- Custo: baixo.
- Reduced motion: `MotionConfig` não corta `pathLength` nem `clipPath`. Use `initial={reduce ? false : …}`.

```tsx
const reduce = useReducedMotion()
// traço real: só em <path> com stroke
<svg viewBox="0 0 24 24" className="size-5 text-brand-deep" aria-hidden>
  <motion.path d="M5 12l5 5L20 7" fill="none" stroke="currentColor" strokeWidth={3}
    initial={reduce ? false : { pathLength: 0 }} whileInView={{ pathLength: 1 }}
    viewport={{ once: true }} transition={{ duration: 0.5, ease: "easeOut" }} />
</svg>
// ilustração preenchida ou PNG: revela com máscara em vez de desenhar
<motion.div initial={reduce ? false : { clipPath: "inset(0 100% 0 0)" }}
  whileInView={{ clipPath: "inset(0 0% 0 0)" }} viewport={{ once: true }}
  transition={{ duration: 0.9, ease: [0.22, 1, 0.36, 1] }}>{ilustracao}</motion.div>
```

### P6. Linha do tempo que preenche

- Exemplo ao vivo: https://ui.aceternity.com/components/timeline (a própria página descreve "scroll beam follow"). Para o layout, veja Zendesk (cards ligados por linha) e RD Station (Marketing → CRM → Atendimento com ✓).
- Onde: **Como funciona** (Diagnóstico → Estratégia → Execução → Evolução). Uma linha cinza fixa fica por baixo de uma linha Azul Pulso que cresce. O círculo de cada passo fica azul quando a linha chega nele. No desktop, use o `scrollYProgress` do P3; no celular, o `useScroll` da própria lista.
- Custo: baixo, com `scaleY` e 4 `whileInView`.
- Reduced motion: linha cheia; os círculos só trocam de cor, sem movimento.

```tsx
const ref = useRef<HTMLOListElement>(null)
const reduce = useReducedMotion()
const { scrollYProgress } = useScroll({ target: ref, offset: ["start 70%", "end 60%"] })
<ol ref={ref} className="relative space-y-12 before:absolute before:inset-y-0 before:left-7 before:w-px before:bg-border">
  <motion.span aria-hidden className="absolute inset-y-0 left-7 w-px origin-top bg-primary"
    style={{ scaleY: reduce ? 1 : scrollYProgress }} />
  {passos.map((passo, i) => (
    <li key={passo.id} className="relative flex gap-6">
      <motion.span className="z-10 grid size-14 shrink-0 place-items-center rounded-full border-2 border-primary bg-background text-primary"
        whileInView={{ backgroundColor: "var(--primary)", color: "var(--primary-foreground)" }}
        viewport={{ margin: "0px 0px -40% 0px" }}>{i + 1}</motion.span>
      <Passo {...passo} />
    </li>
  ))}
</ol>
```

### P7. Troca de cor do fundo entre seções

- Exemplo ao vivo: https://alvarotrigo.com/fullPage/background-change-on-scroll/ (demos em CSS `scroll-timeline` e em IntersectionObserver)
- Onde: no máximo na entrada da CTA final (branco → Azul Pulso). No resto do site, não: o PLANO fixa a base branca e só duas faixas escuras.
- Como: uma camada azul com `opacity` (compositor) no lugar de `background-color` (que repinta a cada frame). O texto aparece depois, para nunca ficar branco sobre branco.
- Custo: baixo com `opacity`; médio se animar `background-color`.
- Reduced motion e Firefox: a faixa já aparece azul (estado final).

```css
.cta { position: relative; isolation: isolate; }
.cta::before { content: ""; position: absolute; inset: 0; z-index: -1; background: var(--primary); }
@media (prefers-reduced-motion: no-preference) {
  @supports (animation-timeline: view()) {
    .cta::before { animation: surge linear both; animation-timeline: view(); animation-range: entry 0% entry 70%; }
    .cta > * { animation: surge linear both; animation-timeline: view(); animation-range: entry 50% entry 90%; }
  }
}
@keyframes surge { from { opacity: 0; } }
```

### P8. Cards que empilham

- Exemplo ao vivo: https://scroll-driven-animations.style/demos/stacking-cards/css/
- Onde: Cases, se virar 3 histórias com foto e um benefício curto (sem percentual, decisão 9).
- Como: só `position: sticky` com `top` crescente. Não precisa de JS.
- Custo: muito baixo, porque é nativo.
- Reduced motion: sticky não é animação, mas `motion-reduce:static` transforma em lista normal.

```tsx
      <CasoCard {...caso} /> {/* foto + benefício curto */}

  ))}
</ol>
```

### P9. Header que ganha sombra ao rolar

- Exemplo ao vivo: https://scroll-driven-animations.style/demos/shrinking-header-shadow/css/
- Onde: a navbar, que hoje não muda ao rolar. Uma sombra suave aparece depois de 80 px.
- Custo: baixo, desde que se anime a `opacity` de um `::after` que já tem a sombra.
- Reduced motion e Firefox: sem sombra; a borda atual já basta.

```css
.navbar::after { content: ""; position: absolute; inset: 0; z-index: -1; opacity: 0;
  box-shadow: 0 8px 24px -12px color-mix(in oklab, var(--brand-deep) 25%, transparent); }
@media (prefers-reduced-motion: no-preference) {
  @supports (animation-timeline: scroll()) {
    .navbar::after { animation: sombra linear both; animation-timeline: scroll(root); animation-range: 0 80px; }
  }
}
@keyframes sombra { to { opacity: 1; } }
```

## 4. Recomendação final: 5 padrões, por seção

O conjunto usa só `motion` (JS), então funciona igual em todos os navegadores, inclusive no Firefox. Regra: **um efeito ligado ao scroll por tela, no máximo.**

| Seção (componente) | Padrão | O que faz |
|---|---|---|
| Página toda (`app/page.tsx`) | **P4 Barra de progresso** | Já montada. Não mexer. |
